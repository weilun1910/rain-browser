# New sources: Granola, Notion and Google Docs | research

Written 2026-11-05 by the Engine agent for round 3. Everything here is read-only, and nothing asks Felix to paste an API key.

Labels: **Checked** means I looked at Felix's Mac, reading a temp copy and printing only counts, field names and header bytes. **Doc** means vendor documentation or public metadata. **Community** means GitHub issues and write-ups. **Inference** means my own reasoning.

## Granola

### The local cache is encrypted now

- **Checked.** `~/Library/Application Support/Granola/` holds `cache-v6.json.enc` (3.1 MB), `granola.db` (7.3 MB plus a 4.2 MB WAL) and several `*.json.enc` files. Neither the cache nor `granola.db` is readable: the database header is random bytes, not `SQLite format 3`. There is no `storage.dek` file.
- **Community.** Granola used a plain `cache-v3.json` until 2025, then `cache-v4.json` in February 2026. A v6 change in March 2026 broke every community parser. Granola's CEO said the cache "can change at any point", pointed people to the MCP and promised a public API (quoted in https://www.weekinvoiceai.com/p/week-in-voice-ai12-granola-scramble).
- **Community.** By June 2026 everything was encrypted. The `.enc` files are AES-256-GCM, and `granola.db` is SQLCipher (https://github.com/openclaw/graincrawl/blob/main/SPEC.md). Since Granola 7.427.0 (16 July 2026) the key lives in a Keychain item tied to Granola's own Apple Team ID, so only Granola's signed app can read it (https://github.com/dannymcc/Granola-to-Obsidian/issues/66). The Granary exporter was archived on 30 July 2026 and moved to the MCP (https://github.com/wassimk/granary/issues/13).
- **Inference.** Reading Granola's files is closed by design on macOS. We don't touch them. The `--granola-dry-run` flag only reports which files exist and whether they're encrypted.

### The official route: Granola's MCP server with OAuth

- **Doc.** `https://mcp.granola.ai/mcp`, Streamable HTTP. The docs say any client with Streamable HTTP and OAuth discovery can connect, and that it uses Dynamic Client Registration, so there is no client ID or secret to enter (https://docs.granola.ai/help-center/sharing/integrations/mcp).
- **Checked (public metadata, fetched cookie-free).** `https://mcp.granola.ai/.well-known/oauth-protected-resource` names the authorization server `https://mcp-auth.granola.ai` and the scope `mcp`. That server's metadata lists a registration endpoint (`/oauth2/register`), PKCE S256, public clients (token auth `none`), refresh tokens, `offline_access`, and a device authorization endpoint.
- **Doc.** Tools include `list_meetings`, `get_meetings` (private notes, AI summary, attendees) and `get_meeting_transcript` (paid plans only). The free plan covers the last 30 days. About 100 requests per minute (https://www.granola.ai/blog/granola-mcp).
- **Community.** A third-party exporter already runs this flow with a loopback redirect on 127.0.0.1 on the free plan, with about 6-hour access tokens (https://github.com/junxit/granola-exporter). It notes the tool output is prose for a model, not a stable format, so parsing has to be forgiving.
- **Doc.** The REST API (`https://public-api.granola.ai/v1`) needs a `grn_` API key and a Business plan (https://docs.granola.ai/help-center/sharing/integrations/granola-api). That breaks the no-key rule.
- **Doc.** CSV export is emailed, once a day, and covers full history including transcripts (https://docs.granola.ai/help-center/sharing/exporting-notes). Good as a later one-time backfill.

### Decision

Build an MCP client inside the app: OAuth discovery, dynamic registration as a public client, PKCE, a sign-in page opened in Felix's default browser and a one-shot loopback listener on 127.0.0.1. Google sign-in refuses embedded web views (https://developers.googleblog.com/en/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/), and Granola signs people in with Google, so the sign-in runs in the default browser, not in our own tab. Then sync with `list_meetings` and `get_meetings` into the local index, slowly, and parse the text output forgivingly. Tokens stay in the app's own folder.

## Notion

- **Checked.** `~/Library/Application Support/Notion/notion.db` is a plain SQLite file (125 MB). From a temp copy: a `block` table with 52,214 rows, 3,469 live pages, 2,701 of them with child blocks, and about 60% of child references present in the cache. Block types include text, bulleted_list, sub_header, page, numbered_list, table_row, to_do, code, callout, quote and transcription. Times are milliseconds. Columns include `properties`, `content`, `parent_id`, `parent_table`, `alive`, `space_id`, `last_edited_time` and `meta_last_access_timestamp`. A `collection` table (226 rows) holds database names and schemas.
- **Doc.** Notion's own engineering post calls the desktop SQLite cache best-effort. It is guaranteed only for pages marked offline, recently visited, favourited or under an offline parent (https://www.notion.com/blog/how-we-made-notion-available-offline). So it holds mostly what Felix has opened.
- **Community.** The record format matches Notion's internal recordMap: `properties.title` is an array of text runs `[text, [[format...]]]` (https://github.com/NotionX/react-notion-x/blob/master/packages/notion-types/src/core.ts). One open-source app tried reading `notion.db` read-only and parsed 1,126 pages in under a second before the maintainer dropped it as out of scope (https://github.com/ARahim3/DigUp/pull/56).
- **Doc.** The hosted Notion MCP (`https://mcp.notion.com/mcp`) supports OAuth with dynamic registration and PKCE, with tools like `notion-search`, `notion-fetch` and `notion-list-recent-pages` (https://developers.notion.com/guides/mcp/build-mcp-client). The REST API needs an integration token or a developer-registered OAuth secret (https://developers.notion.com/docs/authorization).
- **Doc.** Page URLs moved from notion.so to app.notion.com in June 2026. The API's page URL is `https://app.notion.com/p/<slug>-<32 hex id>` (https://developers.notion.com/reference/page). The POC links to `https://www.notion.so/<32 hex id>`, which redirects, and keys pages by their ID so a page read in the browser and the same page from the cache are one item.

### Decision

Read `notion.db` from a temp copy, the way the Chrome importer does. Rebuild each page's text by walking its child blocks in order. Use `meta_last_access_timestamp` as when Felix last opened it. Label it in Settings as pages Notion keeps on this Mac. The hosted Notion MCP is the shipping route, using the same OAuth client code as Granola. It isn't built in this round.

## Google Docs, Sheets and Slides

- **Community.** The export URLs return private documents when the request carries the signed-in session's cookies, and redirect to `accounts.google.com` without them. Docs `export?format=txt`, Sheets `export?format=csv`, Slides `export/txt` (https://docs.rs/crate/nab/0.8.2/source/src/site/google/mod.rs, https://github.com/wkentaro/gdown/blob/main/gdown/download.py).
- **Doc.** The Drive API documents that Workspace files can be "accessed in a browser using the exportLinks field" (https://developers.google.com/workspace/drive/api/guides/manage-downloads).
- **Community.** No documented cookie-based way to list recent documents exists. Drive's web app uses an internal `v2internal` endpoint with a SAPISID-derived header, which is fragile and a terms-of-service grey area (https://brutecat.com/articles/decoding-google/).
- **Doc.** Listing the whole Drive through OAuth needs `drive.readonly` or `drive.metadata.readonly`, which are restricted scopes with a verification and a yearly security assessment (https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification). The Drive desktop Picker with `drive.file` avoids that (https://developers.google.com/workspace/drive/picker/guides/overview-desktop).
- **Checked.** Google Drive for desktop isn't installed on Felix's Mac, so there are no `.gdoc` files to read.

### Decision

Find documents from the browser's own history: every `docs.google.com/document|spreadsheets|presentation/d/<id>` URL seen in this browser or brought in from Chrome. Fetch each one's text export through the app's own WebKit session cookies, a few at a time, and only for documents not refreshed in the last day. A redirect to the sign-in page counts as signed out and stops the run. No listing endpoint is used. The shipping product adds the Drive Picker for documents Felix hasn't opened here.
